# SentinelAI Database Documentation

## What technology is used?
The project has successfully been upgraded from an unreliable in-memory tracker to a permanent, production-ready relational database. 

- **Database:** **SQLite**. This is built directly into Python. It requires zero configuration, zero servers running in the background, and saves everything to a single local file (`sentinel.db`).
- **ORM Module:** **Flask-SQLAlchemy**. This library was used to map pure Python objects into SQL tables automatically to prevent SQL Injection attacks.

## How to View the Database!
All of your project's data is permanently saved inside the `sentinel.db` file automatically generated by `app.py`. However, because it is a highly compressed binary file, if you double-click it normally, it looks like unreadable garbage text.

**To actually view your data visually in a format like Excel:**
1. Open the **Extensions** tab in VS Code (the four square blocks icon on the left).
2. Search for **"SQLite Viewer"**. Install the top result.
3. Double-click the `sentinel.db` file in your project folder. 
4. *(If VS Code shows a warning that it's unreadable, click **"Open Anyway"** and select **"SQLite Viewer"** from the drop-down menu at the very top of your screen).*

You will see a beautiful graphical interface allowing you to navigate the tables (`incidents` and `log_events`) that we created!

## What changes were made?
To make this work across the whole system, the following core structural changes were implemented in the backend:
1. **`requirements.txt` update**: Added `Flask-SQLAlchemy` to explicitly install the database management tools.
2. **Removed RAM Arrays**: In `app.py`, the old `incidents = []` and `alert_log` structures were entirely deleted.
3. **Initialized Tables**: Created rigid `Incident` and `LogEvent` Database Schema models in Python so the `sentinel.db` file generates the correct shape when the app starts.
4. **Endpoint Rerouting**: Refactored the core workflow APIs (`/api/alert`, `api/incidents/<id>/resolve`, `/api/report`) to query and overwrite actual Database rows utilizing `db.session.commit()`.
